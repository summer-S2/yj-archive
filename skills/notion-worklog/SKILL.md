# 노션 작업 기록

## 시작 전

1. 이 스킬 폴더의 `config.local.md`를 읽는다. 노션 ID, 시간대, 프로젝트 매칭표가 있다.
2. 없으면 작업을 멈추고 `config.example.md`를 복사해 채우도록 안내한다. 아래 '필수 스키마'를 갖춘 DB가 없으면 만들지 먼저 묻는다.

## 모드 선택

| 요청 예 | 모드 |
|---|---|
| "오늘 할 일 추가해줘", "내일 할 일 정리" | A. 할 일 등록 |
| "노션에 정리해줘", "이 세션 기록해줘" | B. 세션 정리 |
| "퇴근 전 점검", "오늘 작업 점검" | C. 날짜 점검 (오늘) |
| "11월 6일 작업 점검", "어제 빠진 거 정리" | C. 날짜 점검 (지정일) |

애매하면 어느 모드인지 묻는다.

## 공통 규칙

### 조회

- 날짜·상태 조건 조회는 `notion-query-data-sources`의 **rows 모드 + filter**로 한다. sql 모드는 플랜에 따라 막혀 있다.
  ```json
  {"mode":"rows","data_source_url":"<작업 DB>","filter":{"type":"group","operator":"and","filters":[
    {"type":"property","property":"작업일","propertyType":"date","operator":"date_is","value":{"type":"exact","value":"YYYY-MM-DD"}}]}}
  ```
- 미완료 조회는 `상태` 필터 `status_is` + `{"type":"is_option","value":"시작 전"}` / `"진행 중"`을 `or` 그룹으로 묶는다.

### 작업 DB 속성

- `작업 내용` (title): 결과가 드러나는 한 줄 (예: "알림 미발송 원인 분석")
- `작업일` (date): `"date:작업일:start"`, `"date:작업일:is_datetime": 0`. 여러 날이면 `:end`
- `프로젝트` (relation): 매칭표의 페이지 ID 배열. 매칭 안 되면 미리보기에서 "새 프로젝트 필요"로 묻고 임의로 만들지 않는다
- `상태` (status): `시작 전` / `진행 중` / `완료` / `보관`
- `유형` (multi_select), 아래 값만 쓴다:
  - 코드: `기능 추가`, `기능 변경`, `기능 삭제`, `오류 수정`, `성능 개선`, `리팩토링`, `스타일 수정`, `API 수정`, `기획 수정`, `문서 수정`
  - 업무: `분석`, `조사`, `기획/SPEC`, `문서 작성`, `리뷰`, `QA/테스트`, `운영 대응`, `회의`, `기타`
- `이슈 링크` (url): 대표 링크 1개. 키는 `"이슈 링크"` 그대로 쓴다 (`userDefined:` 접두어는 이름이 id/url인 속성에만 붙는다)
- `메모` (text): 핵심 결과·결론·남은 일, 3줄 이내

### 페이지 본문

완료·진행 중 행은 본문에 상세 내용을 남긴다. 나중에 행을 열어 보면 그때의 근거와 결론이 바로 보여야 회고·보고에 쓸 수 있기 때문이다.

```
## 개요        — 대상(이슈·스레드 링크), 결과 한 줄
## 배경/현상    — 왜 했는지
## 한 일        — 확인·분석·수정 내용, 표·코드 위치
## 결과         — 결론, 수치
## 남은 일      — 후속 작업, 미확인 사항
```

- 해당 없는 섹션은 뺀다. 그날 한 일이 아닌 후속 내용(다른 사람 작업 등)은 "이후 진행 (참고)"로 분리한다.
- 비밀번호·토큰·개인정보 원문은 적지 않는다.

### 미리보기 → 확인

쓰기 전에 항상 보여주고 확인을 받는다. 확인 전에는 쓰지 않는다.

```
| # | 동작 | 작업 내용 | 작업일 | 프로젝트 | 유형 | 상태 | 이슈 링크 |
|---|------|-----------|--------|----------|------|------|-----------|
| 1 | 생성 | ...       | 2026-01-05 | <프로젝트> | 분석 | 완료 | ... |
```

- 각 행 아래에 메모 초안과 본문 섹션 제목을 붙인다.
- 근거가 약한 값은 "(추정)"으로 표시한다. 기록이 사실과 다르면 이후 회고·보고에 오류가 그대로 남는다.

### 쓰기와 보고

- 생성: `notion-create-pages` (parent `data_source_id`), 본문은 `content`에 함께 넣는다.
- 갱신: `notion-update-page` `update_properties`. 본문 추가는 `insert_content`.
- 끝나면 생성·갱신 건수와 페이지 링크를 알려준다. 실패한 행은 오류와 함께 따로 적는다.

## A. 할 일 등록

1. 대상 날짜를 정한다 (기본: 오늘).
2. 사용자가 말한 할 일을 행으로 나누고 프로젝트·유형을 매칭한다.
3. **이월 확인** — 대상 날짜 이전의 `시작 전`·`진행 중` 행을 조회해 목록으로 보여주고, 항목별로 이월 / 그대로 둠 / 보관 중 무엇을 할지 묻는다.
   - 이월: `작업일`을 대상 날짜로 바꾸고 메모 앞에 "M/D부터 이월"을 붙인다.
4. 미리보기 → 확인 → 생성. 새 할 일은 `상태` `시작 전`, 본문은 비워 둔다.

## B. 세션 정리

1. **근거 수집** — 이 세션에서 실제로 한 일만 모은다: 대화에서 수행한 작업과 결론, 수정 파일, 커밋, 다룬 이슈·PR. 추정해서 넣지 않는다.
2. **작업 단위 분할** — 목적이 다른 일은 행을 나누고, 같은 목적의 잔작업은 합친다.
3. **기존 행 대조** — 대상 날짜의 행을 조회한다.
   - 같은 일의 `시작 전`·`진행 중` 할 일이 있으면 새 행 대신 그 행을 갱신한다 (상태 `완료` 또는 `진행 중`, 메모·본문 채움).
   - 같은 일이 이미 `완료`로 있으면 내용만 보충한다.
4. 미리보기 → 확인 → 기록 → 보고.

## C. 날짜 점검 (퇴근 전 / 특정일)

여러 세션에서 한 일을 한곳에서 대조해 빠진 기록을 채운다.

1. **세션 목록** — 번들 스크립트로 그 날짜에 사용자 입력이 있던 세션을 뽑는다.
   ```bash
   python3 -I <이 스킬 폴더>/scripts/sessions.py list YYYY-MM-DD --tz 9
   ```
   세션 기록이 정리 설정으로 지워진 날짜는 결과가 비어 있을 수 있다. 그때는 그 사실을 알리고 커밋·이슈 활동 같은 다른 근거만 쓸지 묻는다.
2. **노션 조회** — 그 날짜의 행과, 그 날짜까지의 `시작 전`·`진행 중` 행을 조회한다.
3. **대조표** — 세션별로 노션 행과 짝을 지어 보여준다.
   ```
   | 세션 (시간·폴더·제목) | 노션 행 | 판정 |
   |---|---|---|
   | 09:20~17:34 <폴더> 모니터링 | 데일리 운영 모니터링 | 기록됨 |
   | 14:03~14:15 <폴더> E2E 계약서 | — | 누락 |
   | 17:46~18:32 <폴더> 인사만 | — | 기록 제외 후보 |
   ```
   질문만 하고 끝난 세션, 이 점검 세션 자체처럼 작업이 아닌 것은 "기록 제외 후보"로 두고 사용자가 정하게 한다.
4. **누락 세션 요약** — 누락 판정 세션만 요약을 읽는다. 전체 기록을 다 읽으면 양이 너무 많기 때문이다.
   ```bash
   python3 -I <이 스킬 폴더>/scripts/sessions.py digest <세션 파일> YYYY-MM-DD --tz 9 --max 400
   ```
   요약으로 결론이 불분명하면 `--max`를 늘려 다시 읽는다. 그래도 불분명하면 "(추정)"으로 표시하거나 사용자에게 묻는다.
5. **미완료 할 일 정리** — 그 날짜의 `시작 전`·`진행 중` 행 중 세션 근거로 끝난 것이 확인되면 `완료` 갱신을 제안한다. 근거가 없으면 상태를 바꾸지 않고 목록만 보여준다.
6. 미리보기 → 확인 → 기록 → 보고.

## 필수 스키마

새 워크스페이스에서 쓸 때 아래 구조로 만든다.

- **프로젝트 DB**: `프로젝트`(title), `상태`(status: 시작 전 / 진행 중·보류 / 완료·취소), `기간`(date), `요약`(text), `작업`(작업 DB와 양방향 relation)
- **작업 DB**: `작업 내용`(title), `작업일`(date), `프로젝트`(relation), `상태`(status: 시작 전 / 진행 중 / 완료·보관), `유형`(multi_select, 위 목록), `이슈 링크`(url), `메모`(text)
- **뷰**: 오늘(작업일 = 오늘, 상태별 그룹), 프로젝트별(프로젝트 그룹), 캘린더, 날짜별(작업일 그룹)
  - 관계형 속성 그룹은 API로 만들면 그룹이 숨김 상태가 될 수 있다. 화면에서 "그룹 편집하기"로 표시를 켠다.
