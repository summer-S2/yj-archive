# 계약목록 심층 인터뷰

> 인터뷰 일시: 2026-04-27

---

## 1차 인터뷰

### 정책서 vs SPEC 불일치

**Q1.** 정책서(`계약목록.md §4`)는 컬럼 21개를 정의하고 있는데, SPEC은 10개 컬럼 + 사이드패널 구조다. 정책서를 SPEC/코드 기준으로 업데이트해야 하는 건지, 아니면 정책서가 "전체 데이터 정의"이고 SPEC이 "v1 화면 노출 범위"인 건지?

**A.** 원래 21개 컬럼을 노출하려고 했는데 테이블에 컬럼이 많으면 가독성이 좋지 않아져서, 중요 데이터만 테이블에 보여주고 상세 정보는 사이드패널로 숨겼다. **정책서가 수정되어야 한다.**

> 결론: 정책서 `§4` 테이블 컬럼 정의를 10개 + 사이드패널 구조로 변경.

**Q2.** 정책서 `§4`에 `평가일시` 컬럼(#2)이 테이블에 있는데, SPEC 테이블 컬럼에는 빠져있다. 의도적으로 테이블에서 뺀 건가?

**A.** Q1과 같은 이유로 사이드패널로 빠졌다.

> 결론: 테이블에서 제외, 사이드패널에서 표시.

### 요약 카드 · 상태 필터

**Q3.** SPEC에 요약 카드와 상태 필터가 있는데, 정책서에는 둘 다 없다 (v2 로드맵에 "필터"로만 언급). SPEC에서 v1 스코프로 끌어온 건가?

**A.** 원래 최종 형태는 백엔드에서 제공하는 필터가 적용되어야 한다. 지금은 전체 데이터를 한번에 불러오기 때문에 프론트에서 임시로 필터 기능을 넣었다. 추후 페이지네이션 도입 시 프론트 필터링이 불가능하므로 백엔드 필터로 전환 예정.

> 결론: v1은 프론트 필터링 (임시), v2에서 백엔드 필터링 + 페이지네이션으로 전환. 정책서에 요약 카드·상태 필터 반영 필요.

**Q4.** 상태 필터의 "해지처리중" 분류 기준이 라벨 문자열 매칭인데, 라벨이 바뀔 때 필터가 깨질 수 있다. 의도적인 결정인가?

**A.** 코드상에는 상태코드를 읽고 문자열로 반환하여 비교하기 때문에 문제 없다.

> 결론: 상태코드 → 라벨 변환 → 라벨 매칭 순서이므로, 라벨 변환 함수가 변경되면 필터도 자동 반영. 이슈 없음.

### 사이드패널

**Q5.** 사이드패널은 v1에서 임시로 넣은 건가, v2에서 계약현황 상세 진입으로 대체되는 건가?

**A.** Q1과 같은 이유로 추가된 것이고, 상세 진입으로 변경되면 형태도 바뀌어야 할 것 같다. 일단 1차 작업이다.

> 결론: v1은 사이드패널(조회 전용). v2에서 상세 진입 방식은 별도 결정.

**Q6.** 사이드패널에서 고객 상세 페이지로 이동하는 동작이 있나?

**A.** 사이드패널은 조회만 된다.

> 결론: 조회 전용. 네비게이션 액션 없음.

### 데이터 · 성능

**Q7.** FA당 고객 수 규모와 초기 로딩 성능은?

**A.** 고려 안 해도 된다.

> 결론: 현재 데이터 규모에서 성능 이슈 없음. v2 페이지네이션에서 대응.

**Q8.** `evaluation` 데이터는 실시간인가 배치 갱신인가? FA가 데이터 기준 시점을 알 수 있는 방법은?

**A.** 현재 실시간이라 갱신 버튼이 일단 필요 없다. 조회하는 시간이 평가일시다.

> 결론: 평가 데이터는 실시간 조회. 평가일시 = API 호출 시점. 테이블에 평가일시 컬럼은 불필요 (사이드패널에서 확인 가능).

### 정렬 · 그룹핑

**Q9.** 동일 고객 내 복수 계약 간 정렬 기준은?

**A.** 서버가 내려주는 순서 그대로.

> 결론: 동일 고객 내 복수 계약 정렬 정책은 추후 수립 예정.

### 고객명 마스킹

**Q10.** 마스킹 처리를 하는 건가? 규칙은?

**A.** 백엔드에서 마스킹해준다.

> 결론: 프론트에서 별도 마스킹 로직 불필요. 백엔드 응답값 그대로 표시.

### 엣지 케이스

**Q11.** 계약 만료일이 null이거나 무기한 계약이 있나?

**A.** 계약은 무조건 1년이다.

> 결론: 현재 계약 프로세스가 1년 단위이므로 만료일 null 케이스는 발생하지 않음.

**Q12.** 수수료출금예정일이 없는 계약이 있나?

**A.** 출금예정일 없는 계약 없다.

> 결론: null 처리 불필요.

### 미결계약과의 관계

**Q13.** 계약목록에는 미결계약(PCT)은 안 나오는 거 맞는가?

**A.** 미결계약 안 나온다.

> 결론: 계약목록은 기계약(CTR)만 표시. 미결계약은 투자제안 상품변경 작업의 계약 관리 탭에서만 노출.
