문제집을 풀다가 틀린 문제를 모은다. 문제 원문은 옮기지 않고 **묻는 내용만 요약**한다.

## 1과목 — 데이터 모델링의 이해

### 1과목 6번 · 3단계 스키마
- **묻는 것**: "모든 사용자 관점을 통합한 조직 전체의 DB 구조"는 어느 스키마인가
- **내 답** 외부 스키마 → **정답** 개념 스키마
- **왜 틀렸나**: '사용자 관점'이라는 말만 보고 외부 스키마를 골랐다. 핵심은 **통합한 조직 전체**다.
- **기억할 것**
  - 외부 스키마 = 사용자별 **View**(여러 개)
  - 개념 스키마 = 전체를 **통합**한 구조(하나)
  - 내부 스키마 = **물리적** 저장 구조
- 관련: [3단계 스키마 · 데이터 독립성](SQLD_개념정리.md#3단계-스키마--데이터-독립성--기출-8회-2026-1--2025-2--2024-2--2023-2--2022-1)

### 1과목 14번 · 속성 vs 도메인
- **묻는 것**: 업무에서 관리하려는, 의미상 더 이상 분리되지 않는 **최소의 데이터 단위**는
- **내 답** 도메인 → **정답** 속성
- **왜 틀렸나**: 도메인과 속성을 헷갈렸다.
- **기억할 것**
  - 속성 = 더 이상 쪼갤 수 없는 **최소 데이터 단위**
  - 도메인 = 속성이 가질 수 있는 **값의 범위**(타입·길이·제약)
- 관련: [엔터티 · 인스턴스 · 속성](SQLD_개념정리.md#엔터티--인스턴스--속성--기출-6회-2026-1--2024-2--2023-2--2022-1), [도메인](SQLD_개념정리.md#도메인--기출-5회-2026-1--2025-1--2023-2--2022-1)

## 2과목 — SQL 기본 및 활용

### 2과목 11번 · 빈 문자열('')과 NULL, 암시적 변환
- **묻는 것**: `VARCHAR2` PK 칼럼과 NULL 허용 칼럼이 있는 테이블에 대한 설명 중 맞는 것
  - 문자 칼럼을 숫자로 비교(`WHERE 서비스번호 = 1`)
  - `''`를 INSERT한 뒤 `= ''` 또는 `IS NULL`로 조회
- **내 답** ①(숫자 형식 값이 하나라도 있으면 `= 1`은 오류 없음) → **정답** ④(SQL Server에서 `''` 입력 후 `IS NULL`로 조회하면 안 나온다)
- **왜 틀렸나**
  - `''` 처리를 DBMS별로 반대로 기억했다.
  - 문자 칼럼 = 숫자 비교 시 변환 방향을 몰랐다.
- **기억할 것**

| DBMS | `''` 입력 시 | `IS NULL` 조회 |
|---|---|---|
| Oracle | **NULL**로 저장 (행은 정상 저장) | 나온다 |
| SQL Server | **빈 문자열** 그대로 | 안 나온다 |

  - Oracle에서 `칼럼 = ''`는 `칼럼 = NULL`과 같아서 **항상 0행**이다.
  - 문자 칼럼 `= 숫자`는 **칼럼 쪽이 숫자로 변환**된다(`TO_NUMBER(칼럼) = 1`). 그래서 숫자로 못 바꾸는 값이 **한 행이라도** 있으면 오류다. 전부 숫자 형식이어야 오류가 없다.
- 관련: [NULL의 특성](SQLD_개념정리.md#null의-특성--기출-16회-2026-3--2025-4--2024-3--2023-3--2022-3), [데이터 타입·암시적 변환](SQLD_개념정리.md#데이터-타입암시적-변환--기출-3회-2026-1--2025-1--2024-1)

### 2과목 13번 · 날짜 범위 조건
- **묻는 것**: "종료일이 2015년 1월이고 가입일시가 2014-12-01 00시"를 조회하는 SQL 네 개 중 결과가 다른 것
- **내 답** ①(`>= 2015-01-01 00:00:00 AND <= 2015-01-31 23:59:59`) → **정답** ④(`TO_DATE('201501','YYYYMM') = 종료일`)
- **왜 틀렸나**: `23:59:59`로 끝나는 범위가 불완전하다고 생각했다. Oracle DATE는 **초 단위까지만** 저장하므로 23:59:59가 그날의 마지막 순간이다.
- **기억할 것**
  - `TO_DATE('201501','YYYYMM')`은 **2015-01-01 00:00:00 한 순간**이다. `=`로 비교하면 그 순간과 같은 행만 나온다.
  - 한 달 전체를 잡는 방법: `>= 1일 AND < 다음달 1일`, `<= 말일 23:59:59`, `TO_CHAR(날짜,'YYYYMM') = '201501'`
  - 가입일시 조건(`CONCAT`, `||`, 튜플 `IN`, `AND` 두 개)은 표현만 다르고 같다.
- 관련: [숫자 · 날짜 · 변환 함수](SQLD_개념정리.md#숫자--날짜--변환-함수--기출-12회-2026-1--2025-4--2024-2--2023-3--2022-2), [WHERE 조건 · 연산자 우선순위](SQLD_개념정리.md#where-조건--연산자-우선순위--기출-15회-2026-3--2025-3--2024-3--2023-3--2022-3)

### 2과목 15번 · 줄 수 세기 + SUM
- **묻는 것**: 줄바꿈이 들어간 값 두 행(`A↵A`, `B↵B↵B`)에 `SUM(LENGTH(C1) - LENGTH(REPLACE(C1, CHR(10))) + 1)`을 적용한 결과
- **내 답** 2 → **정답** 5
- **왜 틀렸나**: 첫 행(2줄)만 계산하고 바깥의 `SUM`을 놓쳤다.
- **기억할 것**
  - `REPLACE(C1, CHR(10))` = 줄바꿈을 **지운** 문자열 (세 번째 인수 생략 = 삭제)
  - 원래 길이 − 지운 뒤 길이 = 줄바꿈 개수, +1 = 줄 수
  - 행별: `A↵A` → 3 − 2 + 1 = **2**, `B↵B↵B` → 5 − 3 + 1 = **3** → SUM = **5**
  - 바깥에 집계 함수(SUM·COUNT)가 있으면 **모든 행을 합친다**.
- 관련: [문자열 함수](SQLD_개념정리.md#문자열-함수--기출-12회-2026-1--2025-2--2024-2--2023-4--2022-3)

### 2과목 17번 · 단순 CASE · DECODE 문법
- **묻는 것**: `CASE WHEN LOC = 'NEW YORK' THEN 'EAST' ELSE 'ETC' END`와 같은 결과를 내는 식
- **내 답** ① `CASE WHEN LOC IS 'NEW YORK' THEN 'EAST' ELSE 'ETC' END` → **정답** ② `CASE LOC WHEN 'NEW YORK' THEN 'EAST' ELSE 'ETC' END`
- **왜 틀렸나**: `IS`를 `=`처럼 쓸 수 있다고 생각했다.
- **보기별**
  - ① **문법 오류**. `IS`는 `IS NULL`·`IS NOT NULL`에만 쓴다.
  - ② 정답. 단순 CASE(`CASE 칼럼 WHEN 값`)로 같은 비교를 한다.
  - ③ **문법 오류**. CASE에 `DEFAULT`는 없다. 나머지는 `ELSE`다.
  - ④ 문법은 정상이지만 **결과가 틀림**. `DECODE(LOC, 'EAST', 'NEW YORK', 'ETC')`는 LOC를 'EAST'와 비교한다. 맞는 순서는 `DECODE(LOC, 'NEW YORK', 'EAST', 'ETC')`
- **기억할 것**: 값 비교는 `=`, `IS`는 NULL 판정 전용. DECODE는 (비교 대상, 비교값, 결과, …, 기본값) 순서
- 관련: [CASE 평가 규칙 · ELSE](SQLD_개념정리.md#case-평가-규칙--else--기출-8회-2025-2--2024-2--2023-2--2022-2), [NULL 관련 함수](SQLD_개념정리.md#null-관련-함수--기출-15회-2026-3--2025-3--2024-3--2023-3--2022-3)
