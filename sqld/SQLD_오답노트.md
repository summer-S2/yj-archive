문제집과 모의고사를 풀다가 틀리거나 이해하지 못한 문제를 모은다. 문제 원문은 옮기지 않고 **묻는 내용만 요약**한다.

## 1과목 — 데이터 모델링의 이해

### 1과목 6번 · 3단계 스키마
- **묻는 것**: "모든 사용자 관점을 통합한 조직 전체의 DB 구조"는 어느 스키마인가
- **내 답** 외부 스키마 → **정답** 개념 스키마
- **왜 틀렸나**: '사용자 관점'이라는 말만 보고 외부 스키마를 골랐다. 핵심은 **통합한 조직 전체**다.
- **기억할 것**
  - 외부 스키마 = 사용자별 **View**(여러 개)
  - 개념 스키마 = 전체를 **통합**한 구조(하나)
  - 내부 스키마 = **물리적** 저장 구조
- 관련: [3단계 스키마 · 데이터 독립성](SQLD_개념정리.md#3단계-스키마--데이터-독립성--기출-8회-2026-1--2025-2--2024-2--2023-2--2022-1)

### 1과목 14번 · 속성 vs 도메인
- **묻는 것**: 업무에서 관리하려는, 의미상 더 이상 분리되지 않는 **최소의 데이터 단위**는
- **내 답** 도메인 → **정답** 속성
- **왜 틀렸나**: 도메인과 속성을 헷갈렸다.
- **기억할 것**
  - 속성 = 더 이상 쪼갤 수 없는 **최소 데이터 단위**
  - 도메인 = 속성이 가질 수 있는 **값의 범위**(타입·길이·제약)
- 관련: [엔터티 · 인스턴스 · 속성](SQLD_개념정리.md#엔터티--인스턴스--속성--기출-6회-2026-1--2024-2--2023-2--2022-1), [도메인](SQLD_개념정리.md#도메인--기출-5회-2026-1--2025-1--2023-2--2022-1)

## 2과목 — SQL 기본 및 활용

### 2과목 11번 · 빈 문자열('')과 NULL, 암시적 변환
- **묻는 것**: `VARCHAR2` PK 칼럼과 NULL 허용 칼럼이 있는 테이블에 대한 설명 중 맞는 것
  - 문자 칼럼을 숫자로 비교(`WHERE 서비스번호 = 1`)
  - `''`를 INSERT한 뒤 `= ''` 또는 `IS NULL`로 조회
- **내 답** ①(숫자 형식 값이 하나라도 있으면 `= 1`은 오류 없음) → **정답** ④(SQL Server에서 `''` 입력 후 `IS NULL`로 조회하면 안 나온다)
- **왜 틀렸나**
  - `''` 처리를 DBMS별로 반대로 기억했다.
  - 문자 칼럼 = 숫자 비교 시 변환 방향을 몰랐다.
- **기억할 것**

| DBMS | `''` 입력 시 | `IS NULL` 조회 |
|---|---|---|
| Oracle | **NULL**로 저장 (행은 정상 저장) | 나온다 |
| SQL Server | **빈 문자열** 그대로 | 안 나온다 |

  - Oracle에서 `칼럼 = ''`는 `칼럼 = NULL`과 같아서 **항상 0행**이다.
  - 문자 칼럼 `= 숫자`는 **칼럼 쪽이 숫자로 변환**된다(`TO_NUMBER(칼럼) = 1`). 그래서 숫자로 못 바꾸는 값이 **한 행이라도** 있으면 오류다. 전부 숫자 형식이어야 오류가 없다.
- 관련: [NULL의 특성](SQLD_개념정리.md#null의-특성--기출-16회-2026-3--2025-4--2024-3--2023-3--2022-3), [데이터 타입·암시적 변환](SQLD_개념정리.md#데이터-타입암시적-변환--기출-3회-2026-1--2025-1--2024-1)

### 2과목 13번 · 날짜 범위 조건
- **묻는 것**: "종료일이 2015년 1월이고 가입일시가 2014-12-01 00시"를 조회하는 SQL 네 개 중 결과가 다른 것
- **내 답** ①(`>= 2015-01-01 00:00:00 AND <= 2015-01-31 23:59:59`) → **정답** ④(`TO_DATE('201501','YYYYMM') = 종료일`)
- **왜 틀렸나**: `23:59:59`로 끝나는 범위가 불완전하다고 생각했다. Oracle DATE는 **초 단위까지만** 저장하므로 23:59:59가 그날의 마지막 순간이다.
- **기억할 것**
  - `TO_DATE('201501','YYYYMM')`은 **2015-01-01 00:00:00 한 순간**이다. `=`로 비교하면 그 순간과 같은 행만 나온다.
  - 한 달 전체를 잡는 방법: `>= 1일 AND < 다음달 1일`, `<= 말일 23:59:59`, `TO_CHAR(날짜,'YYYYMM') = '201501'`
  - 가입일시 조건(`CONCAT`, `||`, 튜플 `IN`, `AND` 두 개)은 표현만 다르고 같다.
- 관련: [숫자 · 날짜 · 변환 함수](SQLD_개념정리.md#숫자--날짜--변환-함수--기출-12회-2026-1--2025-4--2024-2--2023-3--2022-2), [WHERE 조건 · 연산자 우선순위](SQLD_개념정리.md#where-조건--연산자-우선순위--기출-15회-2026-3--2025-3--2024-3--2023-3--2022-3)

### 2과목 15번 · 줄 수 세기 + SUM
- **묻는 것**: 줄바꿈이 들어간 값 두 행(`A↵A`, `B↵B↵B`)에 `SUM(LENGTH(C1) - LENGTH(REPLACE(C1, CHR(10))) + 1)`을 적용한 결과
- **내 답** 2 → **정답** 5
- **왜 틀렸나**: 첫 행(2줄)만 계산하고 바깥의 `SUM`을 놓쳤다.
- **기억할 것**
  - `REPLACE(C1, CHR(10))` = 줄바꿈을 **지운** 문자열 (세 번째 인수 생략 = 삭제)
  - 원래 길이 − 지운 뒤 길이 = 줄바꿈 개수, +1 = 줄 수
  - 행별: `A↵A` → 3 − 2 + 1 = **2**, `B↵B↵B` → 5 − 3 + 1 = **3** → SUM = **5**
  - 바깥에 집계 함수(SUM·COUNT)가 있으면 **모든 행을 합친다**.
- 관련: [문자열 함수](SQLD_개념정리.md#문자열-함수--기출-12회-2026-1--2025-2--2024-2--2023-4--2022-3)

### 2과목 17번 · 단순 CASE · DECODE 문법
- **묻는 것**: `CASE WHEN LOC = 'NEW YORK' THEN 'EAST' ELSE 'ETC' END`와 같은 결과를 내는 식
- **내 답** ① `CASE WHEN LOC IS 'NEW YORK' THEN 'EAST' ELSE 'ETC' END` → **정답** ② `CASE LOC WHEN 'NEW YORK' THEN 'EAST' ELSE 'ETC' END`
- **왜 틀렸나**: `IS`를 `=`처럼 쓸 수 있다고 생각했다.
- **보기별**
  - ① **문법 오류**. `IS`는 `IS NULL`·`IS NOT NULL`에만 쓴다.
  - ② 정답. 단순 CASE(`CASE 칼럼 WHEN 값`)로 같은 비교를 한다.
  - ③ **문법 오류**. CASE에 `DEFAULT`는 없다. 나머지는 `ELSE`다.
  - ④ 문법은 정상이지만 **결과가 틀림**. `DECODE(LOC, 'EAST', 'NEW YORK', 'ETC')`는 LOC를 'EAST'와 비교한다. 맞는 순서는 `DECODE(LOC, 'NEW YORK', 'EAST', 'ETC')`
- **기억할 것**: 값 비교는 `=`, `IS`는 NULL 판정 전용. DECODE는 (비교 대상, 비교값, 결과, …, 기본값) 순서
- 관련: [CASE 평가 규칙 · ELSE](SQLD_개념정리.md#case-평가-규칙--else--기출-8회-2025-2--2024-2--2023-2--2022-2), [NULL 관련 함수](SQLD_개념정리.md#null-관련-함수--기출-15회-2026-3--2025-3--2024-3--2023-3--2022-3)

## 기출 (양파)

### 61회 37번 · 스칼라 서브쿼리가 여러 행을 반환 (🔁 반복해서 틀림)
- **묻는 것**: TBL1(A = 100, 200, 300), TBL2((100, 10), (100, 20), (200, NULL), (300, 5))에서 **오류가 나는** SQL
- **정답**: ③ `SELECT A, (SELECT NVL(B, NULL) FROM TBL2 WHERE TBL1.A = TBL2.A) FROM TBL1`
- **핵심 규칙**: SELECT 절의 스칼라 서브쿼리는 바깥 행마다 **값 1개(0행 또는 1행)**만 돌려줘야 한다. **2행 이상이면 실행 오류**다.
- **행마다 따라가기 (③)**

| TBL1.A | TBL2에서 A가 같은 행 | 서브쿼리 결과 |
|---|---|---|
| 100 | (100, 10), (100, 20) | **2행 → 오류** |
| 200 | (200, NULL) | NULL |
| 300 | (300, 5) | 5 |

- **②와 ③의 차이**
  - ② `SUM(B)` → **집계 함수**라 여러 행을 **1행으로 합친다**. A = 100이면 10 + 20 = 30. 정상.
  - ③ `NVL(B, NULL)` → **단일행 함수**라 행 수를 줄이지 않는다. 2행이 그대로 2행. 오류.
- **보기별**
  - ① `WHERE A IN (서브쿼리)` → IN은 **여러 값을 받는** 연산자라 정상
  - ② 스칼라 + SUM → 정상 (100 → 30, 200 → NULL, 300 → 5)
  - ③ 스칼라 + NVL → **오류** (A = 100에서 2행)
  - ④ `EXISTS` → 있는지만 보므로 행 수와 상관없이 정상
- **JS로 치면**: 스칼라 서브쿼리는 `find`처럼 **하나만** 꺼내야 하는데, ③은 `filter` 결과(배열 2개)를 칸 하나에 넣으려는 것이다. ②는 `reduce`로 합쳐서 하나로 만든 것이다.
- **기억할 것**: 스칼라 서브쿼리 문제는 **바깥 행마다 서브쿼리가 몇 행인지** 세어 본다. 2행 이상이 나오는 행이 하나라도 있으면 오류. 집계 함수(SUM·MAX·COUNT 등)는 1행을 보장하고, 단일행 함수(NVL·UPPER 등)는 보장하지 않는다.
- 관련: [서브쿼리](SQLD_개념정리.md#서브쿼리--기출-18회-2026-3--2025-4--2024-4--2023-4--2022-3)

### 57회 34번 · 대상이 0행일 때 COUNT와 NVL (🔁 반복해서 틀림)
- **묻는 것**: TBL(A, B, C)에서 `SELECT NVL(COUNT(*), 9999) FROM TBL WHERE 1 = 2;`의 결과
- **정답**: **0** (9999가 아니다)
- **풀이**

```
 WHERE 1 = 2  → 항상 거짓 → 남는 행 0개
 GROUP BY 없음 → 전체를 한 묶음으로 보고 결과 1행을 만든다
 COUNT(*) on 0행 → 0   ← NULL이 아니다!
 NVL(0, 9999)  → 0은 NULL이 아니므로 그대로 0
```

- **핵심: 대상이 0행일 때 집계 함수 결과**

| 함수 | 0행일 때 | NVL(…, 9999) 결과 |
|---|---|---|
| `COUNT(*)`, `COUNT(칼럼)` | **0** | 0 |
| `SUM`, `MAX`, `MIN`, `AVG` | **NULL** | 9999 |

  - COUNT는 "몇 개냐"를 세는 거라 하나도 없으면 **0개**다. 나머지는 계산할 값이 없어서 **NULL**이다.
  - 비교: 62회 24번 `NVL(MAX('Y'), 'N')`은 MAX라서 NULL → 'N'이 된다. (단 GROUP BY가 있으면 묶음이 없어 0행)
- **기억할 것**: 0행이면 COUNT만 0, 나머지 집계는 NULL. NVL은 NULL일 때만 바꾼다.
- 관련: [GROUP BY · HAVING · 집계](SQLD_개념정리.md#group-by--having--집계--기출-18회-2026-3--2025-4--2024-4--2023-4--2022-3)

## 모의고사

### 모의고사 281번 · 2차 정규화와 분리 후 관계 (🔁 다시 보기: 아직 이해 못 함)
- **묻는 것**: '일자별매각물건' 엔터티(PK = 매각물건번호 + 매각일자, 일반 속성 = 매각시간·매각장소·최저매각가격 등)에 대한 설명. "몇 차 정규화가 필요한가"와 "분리하면 매각기일과 어떤 관계인가"
- **정답**: ② 2차 정규화가 필요하고, 매각기일 : 일자별매각물건 = **1 : M**
- **예시 데이터**

| 매각물건번호 | 매각일자 | 매각시간 | 매각장소 | 최저매각가격 |
|---|---|---|---|---:|
| A1 | 3/10 | 10:00 | 1호 법정 | 5억 |
| A2 | 3/10 | 10:00 | 1호 법정 | 3억 |
| A3 | 3/10 | 10:00 | 1호 법정 | 7억 |
| A1 | 3/17 | 14:00 | 2호 법정 | 4억 |

- **풀이 순서**
  1. 각 속성에 "이 값을 정하려면 무엇만 알면 되나?"를 묻는다.
     - 최저매각가격 → 물건 + 날짜 **둘 다** 필요 (PK 전체에 종속, 문제없음)
     - 매각시간·매각장소 → **매각일자만** 알면 정해짐 (3/10이면 물건과 상관없이 10:00, 1호 법정)
  2. 매각일자는 복합 PK의 **일부** → **부분 함수 종속** → 2NF 위반 → **2차 정규화** 필요 (1NF는 이미 만족하므로 '1차 정규화 필요'는 틀림)
  3. 매각시간·매각장소를 **매각기일(매각일자, 매각시간, 매각장소)**로 분리한다.
  4. 매각기일 3/10 **하나**에 매각물건 A1·A2·A3 **여러 개**가 연결된다 → **1 : M** (1:1은 틀림)
- **기억할 것**: 복합 PK의 일부에만 종속되는 속성이 있으면 2차 정규화. 그 일부를 키로 떼어 낸 부모와 원래 엔터티는 보통 1:M이다. (모의고사 1123번 상품명 예시와 같은 원리)
- 관련: [정규화](SQLD_개념정리.md#정규화--기출-15회-2026-3--2025-4--2024-4--2023-1--2022-3)

### 모의고사 1365번 · NOT EXISTS vs NOT IN (바깥 테이블에 NULL)
- **묻는 것**: T1(1, 2, 3, NULL), T2(1, 2)에서 두 SQL의 결과 행 수
  - (가) `T1 A WHERE NOT EXISTS (SELECT 1 FROM T2 B WHERE B.COL1 = A.COL1)`
  - (나) `T1 WHERE COL1 NOT IN (SELECT COL1 FROM T2)`
- **정답**: **2, 1**
- **(가) NOT EXISTS: "T2에 짝이 있는 행이 하나도 없으면 통과"**

| T1.COL1 | T2에 `B.COL1 = A.COL1`인 행 | 통과? |
|---|---|:-:|
| 1 | 있음 (1) | ❌ |
| 2 | 있음 (2) | ❌ |
| 3 | 없음 | ✅ |
| NULL | `= NULL`은 항상 UNKNOWN → 짝 **없음** | ✅ |

  - → **2건** (3, NULL). EXISTS는 "있냐 없냐"만 보므로 NULL 행도 "짝 없음"으로 통과한다.
- **(나) NOT IN: `COL1 <> 1 AND COL1 <> 2`가 TRUE여야 통과**

| T1.COL1 | `<> 1` | `<> 2` | AND 결과 | 통과? |
|---|---|---|---|:-:|
| 1 | FALSE | TRUE | FALSE | ❌ |
| 2 | TRUE | FALSE | FALSE | ❌ |
| 3 | TRUE | TRUE | TRUE | ✅ |
| NULL | UNKNOWN | UNKNOWN | UNKNOWN | ❌ |

  - → **1건** (3). 바깥 값이 NULL이면 비교가 UNKNOWN이라 탈락한다.
- **NOT IN과 NULL 정리**

| NULL 위치 | NOT IN 결과 | NOT EXISTS 결과 |
|---|---|---|
| **서브쿼리 쪽**(T2)에 NULL | **전체 0행** | 영향 없음 |
| **바깥 쪽**(T1)에 NULL (이 문제) | **그 NULL 행만 탈락** | NULL 행도 **통과** |

- **기억할 것**: NOT EXISTS는 "짝이 없으면 통과"라 NULL 행도 남고, NOT IN은 NULL이 끼면 UNKNOWN이라 탈락한다.
- 관련: [서브쿼리](SQLD_개념정리.md#서브쿼리--기출-18회-2026-3--2025-4--2024-4--2023-4--2022-3)
