# 한 SPA를 두 도메인에서 쓰기: 호스트 기반 라우팅 (React Router)

기존 웹 프로젝트 안에 **경로 접두어로 분리해 둔 하위 화면 묶음**을, 별도 도메인으로 접속했을 때는 **접두어 없이** 보여 주는 방법 정리.
프로젝트를 새로 만들지 않고 기존 SPA 하나를 그대로 재사용하는 게 목표.

> 표기 규칙: `<...>` 는 프로젝트마다 다른 값으로 바꿔서 사용
> - `<기존 도메인>`: 원래 서비스 도메인
> - `<신규 도메인>`: 하위 화면 묶음만 보여 줄 새 도메인
> - 예시 접두어: `/sub` (실제로는 `<접두어>`)
> - React Router v6 기준

---

## 한눈에 보기

| | 내용 |
|---|---|
| 상황 | 기존 라우트는 `/home`, `/login` … / 하위 묶음은 `/sub/home`, `/sub/login` … 처럼 앞에 접두어가 붙은 절대경로 |
| 원하는 것 | `<신규 도메인>/home` 으로 접속하면 주소창은 그대로, 화면은 `<기존 도메인>/sub/home` 과 같게 |
| 흔한 오답 1 | 인프라 리다이렉트 → 주소창에 `/sub` 가 그대로 보임 |
| 흔한 오답 2 | `basename="/sub"` → basename 은 URL에 **있는** 접두어를 떼는 기능이라, 오히려 주소창에 `/sub` 가 붙음 |
| 흔한 오답 3 | 하위 폴더의 index 만 따로 배포 → SPA는 라우터·컴포넌트·번들이 하나로 묶여 있어서 폴더만 떼어 올릴 수 없음 |
| 해결 | 같은 빌드를 두 도메인에 연결하고, 앱이 **호스트를 보고** 라우트에서 접두어를 떼어 등록 |
| 이름 | 호스트 기반 라우팅(host-based routing) + 경로 접두어 제거(path prefix stripping) |

---

## 1. 선택지 비교

| 방법 | 주소창 | 누가 처리 | 메모 |
|---|---|---|---|
| **리다이렉트** `<신규 도메인>/` → `<신규 도메인>/sub` | `/sub/...` 보임 | 인프라 | 제일 간단. 접두어가 보여도 괜찮으면 이걸로 충분 |
| **서버 리라이트(리버스 프록시)** | 접두어 없음 | 인프라 + 프론트 | 서버가 경로를 바꿔 줘도 SPA 라우터는 **브라우저 주소**를 보고 매칭한다. 결국 프론트 라우터도 손봐야 해서 이점이 적음 |
| **호스트 기반 라우팅 (이 문서)** | 접두어 없음 | 프론트 (인프라는 도메인 연결만) | 앱 안에서 해결. 접두어가 붙은 절대경로 이동만 정리하면 됨 |

> 리다이렉트는 "URL을 바꿔서 다른 곳으로 보내는 것", 이 문서의 방법은 "URL은 그대로 두고 그 자리에 다른 화면을 그리는 것". 이동이 없다.

---

## 2. basename 과 무엇이 다른가

예전에 쓴 basename 은 방향이 반대다.

| | basename | 호스트 기반 라우팅 |
|---|---|---|
| 상황 | 앱이 `<다른 도메인>/우리앱/` 처럼 **하위 경로에 얹혀** 배포됨 | 앱이 도메인 **루트**에 배포됨 |
| 주소창 | `/우리앱/login` (접두어가 **실제로 있음**) | `/login` (접두어 **없음**) |
| 라우터가 하는 일 | URL 앞의 `/우리앱` 을 떼고 나머지로 매칭 | 라우트 정의 쪽에서 `/sub` 를 떼어 등록 |

basename 은 없는 접두어를 만들어 주지 않는다. 그래서 이번 상황엔 맞지 않는다.

---

## 3. 인프라 요청

리다이렉트·리라이트는 필요 없다. 요청은 두 가지면 된다.

1. `<신규 도메인>` 을 기존과 **같은 빌드 산출물**에 연결
2. 모든 경로 요청에 `index.html` 을 반환 (SPA fallback)

---

## 4. 구현

### 4-1. 호스트 판별과 변환 헬퍼

도메인은 코드에 박지 말고 환경변수로 둔다. (예시는 Vite)

```ts
// hostRouting.ts
export const PREFIX = '/sub';

export const isSubHost =
  window.location.hostname === import.meta.env.VITE_SUB_HOST; // <신규 도메인>

/** 신규 도메인이면 '/sub/home' → '/home', 아니면 그대로 */
export const toPath = (path: string) =>
  isSubHost && (path === PREFIX || path.startsWith(`${PREFIX}/`))
    ? path.slice(PREFIX.length) || '/'
    : path;
```

- `startsWith(PREFIX)` 만 쓰면 `/subscribe` 같은 경로도 잘려 나간다. `PREFIX` 자체이거나 `PREFIX/` 로 시작할 때만 자른다.
- 호스트는 앱 시작 시 한 번만 판별하면 된다. 같은 탭에서 도메인이 바뀔 일은 없다.

### 4-2. 라우트 등록: 신규 도메인이면 하위 묶음만, 접두어를 떼서

라우트를 배열(`createBrowserRouter`)로 관리하는 경우:

```ts
// router.tsx
const allRoutes: RouteObject[] = [
  { path: '/home', element: <HomePage /> },
  { path: '/login', element: <LoginPage /> },
  { path: '/sub/home', element: <SubHomePage /> },
  { path: '/sub/login', element: <SubLoginPage /> },
  // ...
];

const subRoutes = allRoutes
  .filter((r) => r.path === PREFIX || r.path?.startsWith(`${PREFIX}/`))
  .map((r) => ({ ...r, path: toPath(r.path!) }));

export const router = createBrowserRouter(isSubHost ? subRoutes : allRoutes);
```

결과:

| 접속 | 매칭되는 화면 |
|---|---|
| `<기존 도메인>/home` | HomePage |
| `<기존 도메인>/sub/home` | SubHomePage |
| `<신규 도메인>/home` | SubHomePage |
| `<신규 도메인>/sub/home` | 매칭 없음 (필요하면 `toPath` 경로로 리다이렉트하는 라우트 추가) |

- 신규 도메인에는 기존 라우트가 **아예 등록되지 않는다.** 두 화면 묶음이 섞일 일이 없다.
- 중첩 라우트(`children`)를 쓰고 있다면 최상위 `path` 만 바꾸면 된다. 자식 경로는 보통 상대경로라 그대로 동작한다.

JSX `<Routes>` 로 관리한다면 하위 묶음 라우트를 배열로 빼 두고 같은 방식으로 `map` 해서 렌더링한다.

### 4-3. 이동: 기존 코드는 그대로, 헬퍼만 끼우기

하위 묶음 코드 곳곳에 `navigate('/sub/...')` 가 이미 있을 것이다. 하나하나 고치지 말고 변환 헬퍼를 거치게 한다.

```ts
// useAppNavigate.ts
export function useAppNavigate() {
  const navigate = useNavigate();
  return (to: To | number, opts?: NavigateOptions) =>
    typeof to === 'number'
      ? navigate(to)
      : navigate(
          typeof to === 'string'
            ? toPath(to)
            : { ...to, ...(to.pathname && { pathname: toPath(to.pathname) }) },
          opts
        );
}
```

```tsx
// 바꾸기 전
const navigate = useNavigate();
navigate('/sub/complete');
<Link to="/sub/home">처음으로</Link>

// 바꾼 뒤
const navigate = useAppNavigate();
navigate('/sub/complete');                 // 그대로 써도 신규 도메인에선 '/complete'
<Link to={toPath('/sub/home')}>처음으로</Link>
```

- 기존 도메인에서는 `toPath` 가 아무것도 안 하므로 동작이 그대로다.
- `<Navigate to=...>`, `redirect()` (loader), `window.location.href = ...` 도 빠짐없이 찾아서 같은 처리를 한다. `'/sub/` 로 전체 검색하면 대부분 나온다.
- 상대경로(`navigate('complete')`, `navigate('../home')`)로 쓴 곳은 손댈 필요 없다.

## 5. 확인할 것

| 항목 | 이유 |
|---|---|
| 본인인증 등 외부 서비스의 리턴·콜백 URL | 도메인이 바뀌면 `<신규 도메인>` 을 따로 등록해야 할 수 있다. 리턴 경로도 `toPath` 를 거쳤는지 확인 |
| 쿠키·세션 도메인 | 쿠키가 `<기존 도메인>` 에 묶여 있으면 신규 도메인에서 로그인 상태가 안 보인다 |
| CORS | API 서버가 허용 Origin 목록을 쓰면 `<신규 도메인>` 추가 필요 |
| 에셋 경로 | 같은 빌드라 절대경로(`/assets/...`)면 문제없음. 상대경로 설정이면 확인 |
| 하위 묶음 → 기존 화면으로 가는 링크 | 신규 도메인엔 기존 라우트가 없어서 404. 이런 링크는 `<기존 도메인>` 전체 URL로 보내거나 없앤다 |
| 분석·로깅의 화면 경로 | 같은 화면이 도메인마다 다른 경로로 찍힌다. 집계 시 호스트로 구분 |

## 6. 테스트

### 로컬에서 신규 도메인 흉내 내기

- `sub.localhost` 처럼 `.localhost` 로 끝나는 이름은 대부분의 브라우저가 로컬로 연결해 준다. 안 되면 hosts 파일에 로컬 주소로 추가
- 환경변수 `VITE_SUB_HOST=sub.localhost` 로 실행
- Vite 개발 서버는 낯선 호스트를 막을 수 있으니 `server.allowedHosts` 에 추가

### 체크리스트

1. `<기존 도메인>/home`, `<기존 도메인>/sub/home` 이 **이전과 똑같이** 동작하는지 (회귀 확인이 제일 중요)
2. `<신규 도메인>/home` → 하위 묶음 첫 화면, 주소창에 `/sub` 없음
3. 하위 묶음 안에서 버튼·링크로 끝까지 진행했을 때 주소창에 `/sub` 가 한 번도 안 나타나는지
4. 신규 도메인에서 새로고침 → 같은 화면 (SPA fallback 확인)
5. 신규 도메인에서 기존 경로(`/login` 이 하위 묶음에 없는 경우 등) 직접 입력 → 의도한 화면 또는 404
6. 본인인증 등 외부 다녀오는 흐름 → 돌아왔을 때 도메인과 경로가 맞는지

### 단위 테스트

`toPath` 는 순수 함수라 바로 테스트할 수 있다. `isSubHost` 는 모듈 로드 시점에 정해지므로, 테스트에서는 호스트를 인자로 받는 버전을 따로 두면 편하다.

```ts
export const stripPrefix = (path: string, enabled: boolean) =>
  enabled && (path === PREFIX || path.startsWith(`${PREFIX}/`))
    ? path.slice(PREFIX.length) || '/'
    : path;

it.each([
  ['/sub/home', true, '/home'],
  ['/sub', true, '/'],
  ['/subscribe', true, '/subscribe'],
  ['/sub/home', false, '/sub/home'],
])('%s (신규 도메인: %s) → %s', (input, enabled, expected) => {
  expect(stripPrefix(input, enabled)).toBe(expected);
});
```

## 7. 정리

- 같은 SPA를 두 도메인에서 쓸 때, 주소창에 접두어를 안 보이게 하려면 **리다이렉트가 아니라 라우트 등록을 바꾼다.**
- basename 은 URL에 **있는** 접두어를 떼는 기능이다. 없는 접두어를 다룰 땐 쓰지 않는다.
- SPA는 폴더 하나만 떼어 배포할 수 없다. 떼려면 빌드 엔트리를 따로 만들어야 하고, 그건 사실상 새 프로젝트다.
- 인프라에는 **같은 빌드 연결 + SPA fallback** 만 요청한다.
- 접두어가 붙은 절대경로 이동은 `toPath` 헬퍼 한 곳을 거치게 해서, 기존 도메인 동작은 건드리지 않는다.
- 도메인이 바뀌면 **콜백 URL·쿠키·CORS** 를 같이 확인한다.
