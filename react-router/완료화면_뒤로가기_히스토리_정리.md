# 여러 단계 신청 후 완료 화면에서 뒤로가기 정리 (React Router)

여러 화면을 거쳐 무언가를 신청하고 완료 화면으로 넘어간 뒤, **뒤로가기를 누르면 이미 지나온 입력 화면이 다시 열리는 문제**를 고친 기록.

> 표기 규칙: `<...>` 는 프로젝트마다 다른 값으로 바꿔서 사용
> - 예시 경로: `/home` → `/apply` → `/apply/step1` → `/apply/step2` → `/apply/confirm` → `/apply/complete`
> - React Router v6 data router(`createBrowserRouter`) 기준

---

## 한눈에 보기

| | 내용 |
|---|---|
| 증상 | 완료 화면에서 뒤로가기 → 이미 끝난 입력 화면(step2, step1 …)이 다시 열림 |
| 원인 | 흐름 화면들이 브라우저 방문 기록에 그대로 남아 있음 |
| 흔한 오답 | 완료로 갈 때 `replace` 만 쓰기 → 확인 화면 한 칸만 지워지고 나머지는 남음 |
| 해결 | ① 흐름 시작 위치를 기록 → ② 신청 성공 시 홈 위치까지 한 번에 뒤로 → ③ 거기서 완료 화면을 새로 쌓기 |
| 결과 | 기록이 `홈 → 완료` 만 남음. 뒤로가기는 홈, 앞으로가기는 갈 곳 없음 |

---

## 1. 먼저 알아야 할 것: 브라우저 방문 기록

브라우저는 **탭마다** 방문 기록을 한 줄로 쌓는다. 뒤로가기·앞으로가기는 이 줄에서 한 칸씩 움직이는 것.

```
[0] 홈 → [1] 신청 시작 → [2] step1 → [3] step2 → [4] 확인
                                                   ▲ 지금 위치
```

웹에서는 아래 셋이 **전부 같은 기록**을 따라간다. 하나만 막으면 나머지로 뚫린다.

- 화면 안의 `<` 버튼 (보통 `navigate(-1)`)
- 브라우저의 뒤로가기 버튼 / 키보드 단축키
- 안드로이드 기기의 물리 백버튼 (WebView 포함)

### 기록을 다루는 방법 3가지

| 방법 | React Router | 하는 일 | 기록 변화 (지금 위치 [2]) |
|---|---|---|---|
| **push** (쌓기) | `navigate('/x')` | 지금 위치 다음에 새 칸을 추가 | `[0] [1] [2] [3]=x` |
| **replace** (바꿔치기) | `navigate('/x', { replace: true })` | 지금 칸을 다른 화면으로 교체 | `[0] [1] [2]=x` |
| **go** (N칸 이동) | `navigate(-2)` | 기록 안에서 N칸 이동 (새 칸 없음) | 위치만 `[0]` 으로 이동 |

### 꼭 기억할 성질 2가지

1. **뒤로 간 상태에서 push 하면, 그 뒤에 있던 칸들은 지워진다.**
   ```
   [0] 홈 → [1] A → [2] B → [3] C      (지금 위치 [3])
   navigate(-3)                        → 위치 [0], 기록은 그대로 [1][2][3] 남아 있음 (앞으로가기 가능)
   navigate('/done')                   → [0] 홈 → [1] done      ([1]~[3] 의 A·B·C 는 사라짐)
   ```
2. **지금 위치보다 앞쪽(과거) 기록은 지울 방법이 없다.** 웹 보안상 막혀 있다.
   새로고침이나 강력 새로고침(`⌘⇧R`)으로도 안 지워진다. 비우려면 **새 탭**을 열어야 한다.

## 2. 문제 상황

### 처음 코드

```tsx
// 확인 화면: 신청 성공하면 완료 화면으로
onSuccess: () => {
  navigate('/apply/complete', { replace: true });
}
```

`replace` 를 쓴 이유는 "완료 화면에서 뒤로가기로 확인 화면에 돌아와 **또 신청하는 것**"을 막으려고. 그런데 기록은 이렇게 된다.

```
[0] 홈 → [1] 신청 시작 → [2] step1 → [3] step2 → [4] 완료
                                                   ▲ 확인 화면 칸만 완료로 바뀜
```

완료 화면에서 뒤로가기 → **[3] step2** 가 열린다. 확인 화면만 지웠지 그 앞 화면들은 그대로 남아 있기 때문.

### 그럼 완료 화면의 "홈으로" 버튼을 replace 로 바꾸면?

```
[0] 홈 → [1] 신청 시작 → [2] step1 → [3] step2 → [4] 홈
```

- 홈에서 뒤로가기 → step2 가 열린다. 여전히 문제.
- 기록에 홈이 두 번 생긴다.

**결론: 완료 화면 한 칸만 다뤄서는 안 되고, 흐름 화면들 전체를 기록에서 걷어내야 한다.**

## 3. 해결 아이디어

1장의 "성질 1"을 이용한다.

```
1) 확인 화면 [4] 에서 홈 [0] 까지 한 번에 뒤로 간다     navigate(-4)
2) 홈 위치에서 완료 화면을 새로 쌓는다(push)          navigate('/apply/complete')

결과:  [0] 홈 → [1] 완료
       ([1]~[4] 의 흐름 화면은 push 때문에 전부 사라짐)
```

- 완료 화면에서 뒤로가기 → 홈
- 완료 화면에서 앞으로가기 → 갈 곳 없음 (흐름 화면이 다시 안 열림)
- 버튼·브라우저·물리 백버튼 모두 같은 결과

남은 질문은 두 가지다.

- **몇 칸 뒤로 가야 하나?** → 4장
- **뒤로 간 "다음에" push 하려면 어떻게 하나?** → 5장

## 4. 몇 칸 뒤로 가야 하나: `history.state.idx`

흐름 중에 사용자가 화면을 왔다 갔다 할 수 있고, 조건에 따라 건너뛰는 단계도 있어서 **칸 수를 하드코딩하면 안 된다.**

React Router(v6 `createBrowserRouter`)는 기록의 각 칸에 **순번**을 적어 둔다.

```js
window.history.state
// { usr: <navigate 할 때 넘긴 state>, key: 'abc123', idx: 3 }
//                                                     ▲ 이 칸의 순번
```

그래서 이렇게 계산한다.

1. 흐름 **첫 화면**(`/apply`)이 열릴 때 그 순번을 저장해 둔다. 예: `1`
2. 흐름 첫 화면은 홈에서만 들어온다. 그래서 **홈 순번 = 첫 화면 순번 − 1** 이다.
3. 신청 성공 시점(확인 화면)의 순번을 읽는다. 예: `4`
4. `이동할 칸 수 = 홈 순번 − 지금 순번 = (1 − 1) − 4 = −4`

> `idx` 는 React Router 가 내부적으로 쓰는 값이라 문서화된 공개 API 는 아니다. 그래서 값이 없을 때(`null`)는 예전 방식(replace)으로 동작하도록 안전장치를 둔다. (7장)

### 코드: 저장소와 헬퍼

상태관리는 어떤 걸 써도 된다. 예시는 zustand.

```ts
// applyFlowStore.ts
import { create } from 'zustand';

interface ApplyFlowState {
  /** 흐름 첫 화면의 기록 순번 */
  flowStartIdx: number | null;
  setFlowStartIdx: (value: number | null) => void;
  clear: () => void;
}

export const useApplyFlowStore = create<ApplyFlowState>((set) => ({
  flowStartIdx: null,
  setFlowStartIdx: (flowStartIdx) => set({ flowStartIdx }),
  clear: () => set({ flowStartIdx: null })
}));

/** React Router 가 history.state 에 남기는 지금 칸의 순번 */
export const getHistoryIdx = (): number | null => {
  const idx = (window.history.state as { idx?: unknown } | null)?.idx;
  return typeof idx === 'number' ? idx : null;
};

/** 결과 화면이 흐름을 걷어내고 열렸다는 표시 — 이때 바로 앞 칸이 홈이다 */
export const FROM_APPLY_FLOW = { fromApplyFlow: true } as const;

export const isFromApplyFlow = (state: unknown) =>
  (state as { fromApplyFlow?: boolean } | null)?.fromApplyFlow === true;
```

### 코드: 흐름 첫 화면에서 순번 기록

```tsx
// ApplyStartPage.tsx  (/apply)
const setFlowStartIdx = useApplyFlowStore((s) => s.setFlowStartIdx);

useEffect(() => {
  setFlowStartIdx(getHistoryIdx());
}, [setFlowStartIdx]);
```

- step1 에서 뒤로가기로 이 화면에 돌아와도 순번은 같아서 문제없다.
- 홈으로 나갔다가 다시 들어오면 새 순번으로 덮어쓴다.

## 5. 뒤로 간 "다음에" push 하기: `popstate`

여기가 제일 헷갈리는 부분.

```ts
navigate(-4);
navigate('/apply/complete');   // ❌ 이렇게 바로 이어 쓰면 안 된다
```

`navigate(-4)` (내부적으로 `history.go(-4)`)는 **비동기**다. 호출한 즉시 이동이 끝나지 않는다. 바로 다음 줄에서 push 하면 아직 확인 화면 위치에서 push 가 일어나 순서가 꼬인다.

브라우저는 `go` 이동이 **끝나면** `popstate` 이벤트를 보낸다. 그 이벤트를 받은 뒤에 push 하면 된다.

```ts
window.addEventListener(
  'popstate',
  () => navigate('/apply/complete', { state: FROM_APPLY_FLOW }),
  { once: true }   // 한 번만 받고 자동으로 리스너 해제
);
navigate(-4);
```

- `{ once: true }`: 이 리스너가 남아 있으면 나중에 사용자가 뒤로가기를 누를 때마다 완료 화면으로 끌려간다. 반드시 한 번만 받는다.
- 리스너는 `navigate(-4)` **보다 먼저** 등록한다.
- `state: FROM_APPLY_FLOW`: 완료 화면에 "바로 앞 칸이 홈이야"라고 알려 주는 표시. 6장에서 쓴다.

### 코드: 확인 화면의 `leaveFlow`

```tsx
// ApplyConfirmPage.tsx
const navigate = useNavigate();
const flowStartIdx = useApplyFlowStore((s) => s.flowStartIdx);

/**
 * 흐름 화면들을 기록에서 걷어낸다 — 홈 위치로 돌아간 뒤 `to` 를 새로 쌓아
 * 뒤로가기는 홈으로, 앞으로가기로는 흐름 화면이 다시 열리지 않게 한다.
 * `to` 가 없으면 홈에서 멈춘다.
 */
const leaveFlow = (to?: string) => {
  const currentIdx = getHistoryIdx();
  // 흐름 첫 화면 바로 앞 칸이 홈이다
  const delta =
    flowStartIdx !== null && currentIdx !== null ? flowStartIdx - 1 - currentIdx : 0;

  // 순번을 모르면(새로고침, 주소 직접 입력 등) 예전 방식으로
  if (delta >= 0) {
    navigate(to ?? '/home', { replace: true });
    return;
  }

  if (to) {
    window.addEventListener('popstate', () => navigate(to, { state: FROM_APPLY_FLOW }), {
      once: true
    });
  }
  navigate(delta);
};
```

쓰는 곳:

```tsx
// 신청 성공
onSuccess: (res) => {
  leaveFlow(res.status === 204 ? '/apply/empty' : '/apply/complete');
},

// "이미 처리 중" 알럿의 확인 버튼 → 홈으로 돌아가기만
onClick={() => leaveFlow()}
```

> 에러 알럿 뒤 홈으로 보낼 때도 같은 문제가 있다. `navigate('/home', { replace: true })` 를 쓰면 `[0] 홈 … [3] step2 → [4] 홈` 이 되어, 홈에서 뒤로가기로 step2 가 열린다. 그래서 여기도 `leaveFlow()` 로 홈 칸까지 돌아간다.

## 6. 완료 화면의 "홈으로" 버튼

해결 후 기록은 `[0] 홈 → [1] 완료` 다. 여기서 "홈으로" 버튼을 push 나 replace 로 만들면:

| 방식 | 결과 | 문제 |
|---|---|---|
| push `navigate('/home')` | `홈 → 완료 → 홈` | 홈에서 뒤로가기 → 완료 화면 |
| replace | `홈 → 홈` | 홈이 두 칸, 뒤로가기 한 번이 씹힌 것처럼 보임 |
| **go `navigate(-1)`** | `홈` (완료는 앞으로가기 칸) | ✅ |

그래서 **바로 앞 칸이 홈일 때만** 한 칸 뒤로 간다. 그걸 판단하려고 5장에서 `state` 를 넘겼다.

```tsx
// ApplyCompletePage.tsx
const navigate = useNavigate();
const { state } = useLocation();

const goHome = () =>
  isFromApplyFlow(state)
    ? navigate(-1)                              // 바로 앞이 홈
    : navigate('/home', { replace: true });     // 주소를 직접 쳐서 들어온 경우 등
```

### 공용 헤더 컴포넌트 주의

공용 헤더(NavBar)에 "홈 아이콘" 이 있고 내부가 `navigate(homePath)` (push) 로 고정돼 있다면, 완료 화면에서는 그 아이콘을 쓰지 말고 **같은 모양의 버튼을 완료 화면에서 따로** 넣는다.

```tsx
<NavBar
  showPrev={false}
  actions={
    <button type="button" onClick={goHome}>
      <HomeIcon />
    </button>
  }
/>
```

공용 컴포넌트 동작을 바꾸면 그걸 쓰는 **다른 화면 전부**의 동작이 바뀐다. 이 문제는 이 흐름에만 있는 것이라 흐름 안에서 해결한다.

## 7. 안전장치와 엣지 케이스

| 상황 | 동작 |
|---|---|
| 흐름 중간에 새로고침 | 메모리 저장소가 비워져 `flowStartIdx = null` → `leaveFlow` 는 예전처럼 replace. (보통 확인 화면 가드가 선택값 없음을 보고 첫 단계로 되돌린다) |
| 확인 화면 주소를 직접 입력 | 위와 같음 |
| `history.state.idx` 가 없는 환경 (memory router 등) | `getHistoryIdx()` 가 `null` → replace |
| 완료 화면에서 저장소 비우기 | 완료 화면 **마운트 시점**에 `clear()`. 확인 화면의 `onSuccess` 에서 비우면, 비우는 순간 확인 화면의 "선택값 없으면 첫 단계로" 가드가 먼저 실행돼 엉뚱한 화면으로 튄다 |
| 같은 탭에서 여러 번 테스트 | 이전 시도의 화면들이 홈보다 **앞쪽** 기록에 남는다. 홈에서 한 번 더 뒤로가면 지난번 step 화면이 나올 수 있음. 웹에서 앞쪽 기록은 못 지운다 → 테스트는 **새 탭**에서 |

## 8. 테스트

### 단위 테스트 (vitest + Testing Library + jsdom)

`createMemoryRouter` 는 브라우저 기록을 안 써서 이 문제를 재현할 수 없다. **`createBrowserRouter`** 로 jsdom 의 실제 `window.history` 를 쓰게 해야 한다.

```tsx
const renderBrowserFlow = async () => {
  window.history.replaceState(null, '', '/home');
  const router = createBrowserRouter([
    { path: '/home', element: <div data-testid="home" /> },
    { path: '/apply', element: <ApplyStartPage /> },
    { path: '/apply/step1', element: <div /> },
    { path: '/apply/step2', element: <div /> },
    { path: '/apply/confirm', element: <ApplyConfirmPage /> },
    { path: '/apply/complete', element: <ApplyCompletePage /> }
  ]);
  render(<RouterProvider router={router} />);

  const homeIdx = window.history.state.idx as number;
  await router.navigate('/apply');
  await waitFor(() => expect(useApplyFlowStore.getState().flowStartIdx).not.toBeNull());
  await router.navigate('/apply/step1');
  await router.navigate('/apply/step2');
  await router.navigate('/apply/confirm');
  return { router, homeIdx };
};

it('완료 후 뒤로가기 → 홈, 앞으로가기 → 그대로', async () => {
  const { router, homeIdx } = await renderBrowserFlow();
  await submit(); // 동의 체크 → 신청 버튼 클릭

  await waitFor(() => expect(router.state.location.pathname).toBe('/apply/complete'));
  expect(window.history.state.idx).toBe(homeIdx + 1);   // 홈 바로 다음 칸

  await router.navigate(1);                              // 앞으로가기
  expect(router.state.location.pathname).toBe('/apply/complete');

  await router.navigate(-1);                             // 뒤로가기
  await waitFor(() => expect(router.state.location.pathname).toBe('/home'));
});

it('완료 화면 홈으로 → 홈이 기록에 겹치지 않는다', async () => {
  const { router, homeIdx } = await renderBrowserFlow();
  await submit();
  fireEvent.click(await screen.findByText('홈으로 이동하기'));
  await waitFor(() => expect(router.state.location.pathname).toBe('/home'));
  expect(window.history.state.idx).toBe(homeIdx);       // 새 칸이 아니라 원래 홈 칸
});
```

> **테스트가 진짜 버그를 잡는지 확인하기**: 고친 코드를 잠깐 예전 코드(그냥 replace)로 되돌리고 돌려 본다. 테스트가 **실패해야** 정상이다. 그대로 통과하면 그 테스트는 아무것도 검증하지 않는 것.

### 실제 브라우저 확인

jsdom 과 실제 브라우저는 다르게 동작할 때가 있으니 브라우저에서도 꼭 본다. 실제로 이번에 단위 테스트는 통과했지만, 브라우저에서 앞으로가기를 눌러 보고서야 "앞으로가기 기록이 남는" 문제를 찾았다. 그래서 처음의 "흐름 첫 칸을 replace" 방식에서 "홈까지 간 뒤 push" 방식으로 바꿨다.

1. **새 탭**에서 홈부터 시작
2. 개발자도구 콘솔에서 단계마다 확인
   ```js
   ({ path: location.pathname, idx: history.state.idx, len: history.length })
   ```
3. 신청 후 확인할 것
   - 완료 화면의 `idx` 가 홈 `idx + 1` 인지
   - `history.length` 가 줄었는지 (앞으로가기 기록이 지워졌다는 뜻)
   - 브라우저 **뒤로가기 버튼** → 홈
   - 브라우저 **앞으로가기 버튼** → 이동 없음
   - 완료 화면 "홈으로" → 홈, 거기서 뒤로가기 → 홈 이전 화면 (홈이 두 번 나오면 실패)
4. 안드로이드 기기가 있으면 물리 백버튼도 한 번

---

## 9. 정리

- 웹의 뒤로가기는 **화면 버튼 / 브라우저 버튼 / 물리 백버튼이 모두 같은 기록**을 따른다. 화면 버튼만 고치면 안 된다.
- `replace` 는 **지금 한 칸**만 바꾼다. 여러 단계 흐름을 지우는 데는 부족하다.
- 흐름을 통째로 지우려면 **흐름 시작 직전 칸까지 `go` 로 돌아간 뒤 push** 한다. push 가 앞쪽 기록을 지운다.
- `go` 는 비동기라 **`popstate` 를 `once` 로 받아서** 그다음에 push 한다.
- 몇 칸 갈지는 하드코딩하지 말고 **`history.state.idx`** 로 계산하고, 값이 없으면 replace 로 대체한다.
- 결과 화면의 "홈으로" 는 바로 앞이 홈일 때 **`navigate(-1)`**. push·replace 는 기록을 더럽힌다.
- 지금보다 앞쪽(과거) 기록은 어떤 방법으로도 못 지운다. 테스트는 새 탭에서.
